- **Краткое описание:**  

Проект посвящён построению сервиса рекомендаций фильмов на основе пользовательских оценок.  
Используются открытые датасеты, простые модели коллаборативной фильтрации и baseline-модели на контентных признаках.  
Результат - REST API, который формирует cold-start рекомендации по жанровой анкете и warm-start рекомендации по сохранённым оценкам текущего пользователя

## 2. Структура проекта

Проект организован в следующей структуре:

- `README.md` - основная документация проекта: описание, установка, запуск, API и тестирование.
- `requirements.txt` - зависимости проекта: библиотеки Python, необходимые для установки, обучения моделей, запуска API и тестов.
- `Dockerfile` - инструкция для сборки Docker-образа с Python, системными зависимостями, библиотеками и кодом проекта.
- `compose.yaml` - конфигурация Docker Compose для запуска подготовки проекта, тестов и API в отдельных контейнерах.
- `.dockerignore` - список файлов и папок, которые не копируются в Docker-образ.
- `.gitignore` - список локальных, временных и автоматически создаваемых файлов, которые не добавляются в Git.
- `report.md` - отчёт по проекту: постановка задачи, данные, эксперименты и результаты.
- `self-checklist.md` - чеклист самопроверки проекта перед сдачей.
- `notebooks/` - экспериментальные ноутбуки.
- `src/` - основной код проекта.
- `data/` - загружаемые и создаваемые данные.
- `configs/` - конфигурационные файлы с путями, параметрами моделей, рекомендаций и обработки данных.
- `tests/` - автоматические тесты.
- `artifacts/` - результаты обучения и экспериментов.
- `user_data/` - пользовательские данные.

## 3. Требования и установка

Проект можно запустить двумя способами:

- вручную в локальном Python-окружении;
- в Docker-контейнерах.

### 3.1. Требования

Для ручного запуска:

- Python `>= 3.11`;
- Git, если проект клонируется из репозитория.

Для запуска через Docker:

- Git, если проект клонируется из репозитория;
- Docker Engine или Docker Desktop;
- Docker Compose.

### 3.2. Ручная установка

Перейти в папку проекта:

```bash
cd project
```

Создать виртуальное окружение:

```bash
python -m venv .venv
```

Активировать окружение.

Windows:

```bash
.venv\Scripts\activate
```

Linux / macOS:

```bash
source .venv/bin/activate
```

Обновить `pip` и установить зависимости:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Один раз выполнить подготовку проекта:

```bash
python -m src.setup_project --cleanup-data
```

Команда:

* скачивает наборы данных MovieLens;
* формирует каталог фильмов;
* обучает CatBoost и глобальную SVD;
* сохраняет модели и метаданные;
* создаёт начальные пользовательские файлы;
* удаляет исходные обучающие данные после завершения.


### 3.3. Установка и запуск через Docker

При использовании Docker создавать виртуальное окружение и вручную устанавливать Python-зависимости не требуется. Они устанавливаются внутри образа из `requirements.txt`.

Перейти в папку проекта:

```bash
cd project
```

Проверить конфигурацию Docker Compose:

```bash
docker compose config
```

Собрать образ:

```bash
docker compose build
```

Один раз выполнить подготовку данных и моделей:

```bash
docker compose run --rm setup
```

Повторно запускать `setup` требуется только при необходимости заново сформировать каталог, модели и метаданные.

После изменения исходного кода или `requirements.txt` необходимо пересобрать образ:

```bash
docker compose build
docker compose up -d api
```

## 4. Как запустить проект

ВАЖНО! Перед запуском стоит проделать инструкции из пункта 3

### 4.1. Если устанавливали вручную 

```bash
cd project
.venv\Scripts\activate
python -m uvicorn src.api.app:app --host 0.0.0.0 --port 8000
```

### 4.2. Если устанавливали через Docker

```bash
cd project
docker compose up -d api
```

После запуска доступны:

* проверка состояния: `http://localhost:8000/health`;
* Swagger UI: `http://localhost:8000/docs`.

Остановить сервис:

```bash
docker compose down
```

Сервис поднимается на порту 8000

### 4.3. Эндпоинты

  - GET /health - Проверяет, что сервис запущен.
  - GET /questionnaire - Выдает текущую анкету пользователя для cold-start рекомендаций.
  - POST /cold-start/recommendations - Сохраняет анкету пользователя и возвращает cold-start рекомендации. Использует CatBoost-модель.
  - GET /movies - Возвращает фильмы из каталога по части названия.
  - GET /ratings - Возвращает сохранённые пользовательские оценки вместе с названиями фильмов.
  - POST /ratings - Валидирует и сохраняет пользовательские оценки фильмов.
  - POST /warm-start/recommendations - Возвращает warm-start рекомендации или сообщение о нехватке оценок

### 4.4. Проверка работоспособности

  1. открыть Swagger UI в браузере: `http://127.0.0.1:8000/docs`; 
    - проверить состояние сервиса командой: 
      ```bash 
        curl http://127.0.0.1:8000/health 
      ```
    - Ожидаемый ответ: 
      ```json 
      { "status": "ok" } 
      ``` 
  2. выполнить автоматические тесты из корня проекта (пункт 6)
