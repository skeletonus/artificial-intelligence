## 2. Постановка задачи и контекст

1. **Предметная область и задача:**
   - Решаемая задача: регрессия. Модель предсказывает оценку пользователя фильму и на основе этого выдает конечный список;
   - Потенциальный пользователь: обычное физическое лицо, не представляющее никакую коммерческую организацию, желающий найти подборку фильмов.
   - Сценарий: пользователь заполняет анкету и получает рекомендованные фильмы или ставит оценки фильмам и получает более персонализированные рекомендации.

2. **Формулировка задачи в терминах ML/ИИ:**
   - Вход модели: данные пользователя, объединенные с данными о фильмах;
   - Выход модели: потенциальная оценка пользователя фильму от 0.5 до 5;
   - Требования: точность, скорость.

3. **Целевые метрики качества:**
   - Метрики оценки модели: RMSE, MAE;
   - Метрики выбраны в соответствии с задачей регрессии.

## 4. Модели и подходы

В экспериментах 02-05 были рассмотрены бэйзлайны моделей с различной архитектурой. В тех же экспериментах строились их более совершенные версии, перебирались гиперпараметры и выбиралась лучшая модель.

1. **Базовые (baseline) модели:**
   - GlobalAvgBaseline (Оценивает все фильмы глобальной средней оценкой). RMSE: 1.078 | MAE: 0.853
   - LinearRegression. RMSE: 1.019 | MAE: 0.794
   - DecisionTree. RMSE: 1.021 | MAE: 0.812
   - MLP. RMSE: 1.014 | MAE: 0.803
   - BiasBaseline. RMSE: 1.025 | MAE: 0.798

2. **Улучшенные модели и эксперименты:**
   - LinearRegression: Ridge, Lasso, ElasticNet (`notebooks/exp02_LinearRegression.ipynb`)
   - DecisionTree: RandomForest, GradientBoosting, CatBoost (`notebooks/exp03_DecisionTree.ipynb`)
   - MLP: NeuralCF (`notebooks/exp04_NeuralNetworks.ipynb`)
   - BiasBaseline: KNNWithMeans, KNNBaseline, SVD, SVDpp, NMF (`notebooks/exp05_CollaborativeModels.ipynb`)

3. **Нейросетевые модели:**
   - MLP: стандартный персептрон с 1 выходом
   - NeuralCF - тот же самый MLP, но с embedding.

## 5. Экспериментальный протокол и результаты

1. **Экспериментальный протокол:**
   - Выборка: train/val/test, разбитая по времени
   - Расчет метрик: на val при подборе гиперпараметров, на test при итоговой оценке

2. **Сравнение моделей по метрикам:**
   - cold-start

      | Модель / конфигурация         | Описание                                         | RMSE      | MAE       | Комментарий                          |
      |-------------------------------|--------------------------------------------------|-----------|-----------|--------------------------------------|
      | GlobalAvgBaseline             | Ставит всем фильмам среднюю оценку по датасету   | 1.078     | 0.853     | Простая стартовая точка              |
      | Lasso                         | Линейная регрессия с l1-регуляризацией           | 1.015     | 0.795     | Лучшая из линейной регрессии         |
      | CatBoost                      | Ансамбль последовательных деревьев               | 1.010     | 0.793     | Финальная модель. Лучшая из деревьев |
      | NeuralCF                      | MLP c embedding                                  | 1.010     | 0.799     | Лучшая из нейронных сетей            |   

   - warm-start

      | Модель / конфигурация         | Описание                                         | RMSE      | MAE       | Комментарий                                         |
      |-------------------------------|--------------------------------------------------|-----------|-----------|-----------------------------------------------------|
      | BiasBaseline                  | rating = glob_avg + b_i + b_u                    | 1.025     | 0.798     | Простая стартовая точка                             |
      | SVD                           | Строит скрытые признаки пользователей и фильмов  | 1.026     | 0.797     | Финальная модель. Проста и точна                    |
      | SVDpp                         | Учитывает факт оценки.                           | 1.029     | 0.799     | Самая сильная коллаборативная модель, перегруженная |
      
3. **Выбор финальной модели:**
   - cold-start - CatBoost. Быстрая модель в обучении и предсказаниях, интерпретируема, лучшие метрики, не перегружена. 
   - warm-start - SVD. Сильная модель, хорошие результаты по метрикам. Намного быстрее, чем SVDpp, хотя и не может поймать столь сложных зависимостей.
   - trade-off’ы: вес модели, скорость обучения и предсказания, интерпритируемость

## 6. Архитектура решения и сервис

1. **Архитектура пайплайна:**
   Загрузка данных -> Предобработка -> Разбиение на train/val/test выборки -> Обогащение -> Обучение CatBoost и SVD моделей -> Использование в сервисе

2. **API и endpoints:**
   - Эндпоинты:
      - GET /health - Проверяет, что сервис запущен.
      - GET /questionnaire - Выдает текущую анкету пользователя для cold-start рекомендаций.
      - POST /cold-start/recommendations - Сохраняет анкету пользователя и возвращает cold-start рекомендации. Использует CatBoost-модель.
      - GET /movies - Возвращает фильмы из каталога по части названия.
      - GET /ratings - Возвращает сохранённые пользовательские оценки вместе с названиями фильмов.
      - POST /ratings - Валидирует и сохраняет пользовательские оценки фильмов.
      - POST /warm-start/recommendations - Возвращает warm-start рекомендации или сообщение о нехватке оценок
   - Параметры cold-start predict (POST /cold-start/recommendations):
      - Анкета с оценками всех жанров
      - Минимальная оценка жанра для попадания в рекомендации
      - Размерность топа - N
   - Параметры warm-start predict (POST /warm-start/recommendations)
      - Оценки пользователя movieId-rating
      - Размерность топа - N

3. **Технологический стек:**

   - Библиотеки и фреймворки
      - FastAPI - фреймворк для создания REST API рекомендательной системы
      - Uvicorn - ASGI-сервер для запуска FastAPI-приложения
      - Pydantic - библиотека для валидации входных данных и описания схем запросов и ответов
      - CatBoost - библиотека для обучения модели cold-start рекомендаций
      - scikit-surprise - библиотека для создания SVD-модели warm-start рекомендаций
      - scikit-learn - библиотека для подготовки данных, обучения моделей и расчёта метрик
      - pandas - библиотека для загрузки и обработки табличных данных
      - NumPy - библиотека для выполнения численных операций
      - Joblib - библиотека для сохранения и загрузки обученных моделей
      - PyYAML - библиотека для чтения настроек из YAML-файлов
      - Pytest - фреймворк для автоматического тестирования проекта
      - httpx2 - библиотека для выполнения HTTP-запросов при тестировании API
      - Docker - платформа для контейнеризации приложения
      - Docker Compose - инструмент для запуска и управления контейнерами проекта

   - Используется Docker, доступные команды:
      - `docker compose build` - собирает образ
      - `docker compose run --rm setup` - подготовка данных и моделей
      - `docker compose run --rm test` - запуск тестов
      - `docker compose up -d api` - запуск сервиса

## 7. Наблюдаемость, конфигурация и безопасность

1. **Логи и наблюдаемость:**

   Сервис использует стандартные логи Uvicorn, в которых отображаются запуск приложения, HTTP-запросы, статусные коды и необработанные ошибки. 
   Скрипт установки дополнительно выводит сообщения о загрузке данных, обучении моделей и создании артефактов.

   Работоспособность сервиса можно проверить:

   - запросом `GET /health`;
   - через Swagger UI по адресу `http://127.0.0.1:8000/docs`;
   - запуском автоматических тестов:

2. **Конфигурации:**

   Основные настройки вынесены в файл configs/config.yaml. Без изменения исходного кода можно настроить:

   - Пути к данным, моделям, метаданным и пользовательским файлам;
   - Параметры загрузки и разделения датасетов;
   - Диапазон допустимых оценок;
   - Параметры обучения CatBoost и SVD;
   - Минимальную оценку жанра для cold-start;
   - Минимальное число оценённых фильмов для warm-start;
   - Параметры подготовки признаков и каталога фильмов.

   Файл .env в текущей версии не используется, поскольку сервис не требует токенов, паролей или подключения к внешней базе данных.

3. **Безопасность:**

   В проекте не используются секретные ключи, токены и пароли, поэтому чувствительные значения не хранятся в исходном коде и конфигурации. 
   В репозитории отсутствуют персональные данные пользователей, кроме локальных файлов анкеты и оценок, создаваемых при работе сервиса.
